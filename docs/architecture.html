System Documentation

Factory Inventory Management — Architecture

A two-process demo application: a Vue 3 single-page app talking REST to a FastAPI backend that serves in-memory mock data loaded from JSON files. No database, no auth, no build-time coupling between the two.

Vue 3.4 + Vite 5 FastAPI + Pydantic v2 Python ≥3.11 axios JSON mock data 40 backend tests (pytest)
01

System Architecture

Three tiers, two processes. The client and server run independently on ports 3000 and 8001; the data layer is plain JSON read into module-level Python lists at import time.

There is no Vite proxy: api.js and Reports.vue hardcode http://localhost:8001/api, and the server allows it with allow_origins=["*"]. .env.example is empty — no environment variables are read anywhere.

03

Data Flow

One pattern repeated across every view: shared filter refs drive refetches; the server filters in memory; views derive display data with computed properties.

User changes a filter
FilterBar (mounted in App.vue) mutates the singleton refs in useFilters.js — Time Period, Warehouse, Category, Order Status.
Views react
Each routed view watches those refs and calls its api.js functions with getCurrentFilters() → {warehouse, category, status, month}.
api.js serializes query params
Params equal to 'all' are skipped; axios issues GETs against http://localhost:8001/api.
FastAPI filters in memory
apply_filters() + filter_by_month() run list comprehensions over module-level lists loaded by mock_data.py; responses validated by Pydantic models.
Views render via computed properties
Raw responses land in refs; charts, KPIs, and tables are derived with computed(). Detail modals receive rows via props — no component makes its own API calls.

05

Notable Findings

Quirks worth knowing before extending the codebase — mostly half-built features left on both sides of the API boundary.

Dead code on both ends of the API
api.js exports tasks CRUD (/api/tasks) and purchase-order calls that no component uses — and no server endpoint implements. Mirror image on the server: PurchaseOrder / CreatePurchaseOrderRequest models exist and purchase_orders.json is loaded, but it's an empty array with no routes. Only live trace: the has_purchase_order flag on /api/backlog.
Backlog.vue is orphaned
A complete 152-line view with no route in main.js and no imports anywhere. TasksModal similarly manages tasks in local state only, never touching the API.
Reports.vue bypasses api.js
It calls axios directly with its own hardcoded base URL — the only view that does. Changing the API host means editing two files.
Data resets on every server restart
mock_data.py loads JSON at import time into module-level lists. Nothing writes back to disk; generate_data.py is the only writer and runs offline (17-SKU catalog, randomized 2025 dates).
Wide-open CORS instead of a dev proxy
allow_origins=["*"] with credentials — fine for a demo, replace with a Vite proxy or an allowlist before anything real.
